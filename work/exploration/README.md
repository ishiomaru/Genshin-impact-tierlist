# 次期製品の比較試作

2026-10-29。v1とは別の探索用コード。原文・`src/`・既存試作は変更しない。

起動：ルートで `npm run dev` → http://127.0.0.1:5173/work/exploration/ 。A/B/Cは同じURLの `?concept=a` / `b` / `c` で直接開ける。

## 試作前に定めた問いと採択条件

1. 読者の次の行動を助けるのは、評価の比較、具体的な編成配分、判断の根拠確認のどれか。
2. 条件を操作した結果と、まだ判断できない範囲を、狭い画面でも同時に伝えられるか。

同じサンドローネ・ヌヴィレット・スクロースの点数・条件・留保を中心に、Aは用途別比較、Bは4人編成の割当、Cは主張からの根拠追跡を作る。Bの重複を試すためヴェスナ・マーヴィカも使用する。Aだけデータが少ない等の差をつけない。

採択は合計点で決めない。①根拠のある回答に到達できる、②原文の範囲外を見分けられる、③現在のデータで成立し更新可能、④再訪する理由がある、⑤モバイルでも中心操作が成立、を優先する。人間の需要・理解度は別途検証する。

## 動く範囲

- A：3運用の共通軸比較、4プリセット、★4低凸の場合の適用外表示、1軸±0.5の感度幅。
- B：2/3編成の具体的な割当、手で確定した正規名の完全一致による重複検出、オデット未所持の場合の不足表示。任意の代替を自動推測しない。本実装では安定したキャラIDへ移す。
- C：3つの問い、原著者の結論・今回の再計算・外部本文で確かめた範囲の分離、主張単位の出典、版に結びつく比較メモの端末保存と復元。

各案とも完成製品ではない。全77運用の編集、任意所持情報、現行ボスへの割当、DPSの新規計算、クラウド同期は未実装。画面にその範囲を表示する。履歴は実在する原文1版のみで、架空の過去Tierを作らない。

## 選好確認後の統合試作

ユーザー回答「A,Bは両方とも重視したい」を受け、`?concept=plan` に追加。「比較→具体例を仮置き→重複・不足の確認→候補へ戻る」が一続きになるかを試す。独立したA/B/Cは比較用に維持する。編成間の重複を候補の近くでも予告し、仮置きした対象枠へ戻る。所持はオデットの未入力／所持／未所持だけで、全所持判定とはしない。

統合試作の保存は別キー `genshin-exploration-plan-v1` に資料ハッシュ・比較視点・代表例ID・オデットの指定状況を保存する。別資料版や不正な代表例は自動復元しない。汎用の編成最適化やガチャ推薦は行わない。

`prototype.mjs` は既存の実データと計算関数を読む。編成の固定4枠は原文を人手で構造化した試作データであり、他候補の任意補完ではない。外部照合メモは今回取得した本文の限定的な観察で、原著者のTierの追認ではない。画像は既存同梱素材を再利用。

## 証拠と再現

- `audit-v1.mjs`：既存 `tests/browser.mjs` の保存先だけを変更した写し。既存証拠を上書きしない。
- `inspect.mjs`：今回固有のv1観察と新試作の操作・スクリーンショット検査。
- `evidence/`：今回の実行結果。保存画像を実際に開いたか、どの状態を見たかは親のレポートに記す。

試作のメモは専用キー `genshin-exploration-notebook-v1`。v1の個人データは読み書きしない。
