# 開始指示

このプロジェクトの素材から、完成度の高いWebサイトを実際に制作してください。

素材は `source/` 内にあります。依頼で別のパスが指定されたら、そちらを優先します。完成サイトは既存の構成に合わせ、構成がなければ `site/` に作ってください。`experiment/` は研究用の表示試作であり、デザインの正解や必須機能ではありません。

最優先は最終成果物の品質です。情報の理解、追加調査、企画、情報設計、表現、素材の準備、実装、ブラウザでの検査、改善まで進めてください。計画や企画書だけで終了しないでください。

私は完成像を事前に明確に持っていません。これを要件不足として停止せず、素材と利用目的から仮説を立て、実物で確かめてください。細部を逐一質問せず、可逆な判断は自律的に行ってください。私の選好が採択を変えそうな場面では、同じ内容を使った少数の比較可能な実物を示し、短い選択で判断できるようにしてください。任意の好みの回答がなければ、理由を記して有望な案で進めてください。

最初に環境と素材を確認してください。既存のAGENTS.md、作業中の変更、実行できるブラウザ、検索や画像生成・取得の手段を把握してください。利用できない機能を使ったと報告しないでください。必要な技術仕様は公式資料で確認してください。

素材の見出しをそのまま画面仕様にせず、重要な主張・条件・根拠・例外・関係性と、読者の主要な行動を把握してください。意味の正確性と、元の主張の強さを保ってください。数値、図、順位、因果関係を推測で補わないでください。資料の主張を忠実に表示したことと、外部の事実として検証したことを区別してください。

重要な内容には、どのような表現が適しているかを検討してください。文章、実画像、図解、表、比較、条件切替、動き、独自の部品などを候補にできます。使用を義務にせず、読者への役割から採否を決めてください。画像・図が有効なのに検討せず文章だけで終えることも避けてください。

最初の案へ固定する危険がある場合は、最も重要かつ難しい代表内容で、情報構造や中心操作の異なる少数案を動く形にしてください。数は必要に応じて決めてください。色替えだけの案、長い企画書だけの比較、必須操作を動かさない見本は避けてください。案には目的、内容固有の判断、苦手な行動を短く添え、採択理由を残してください。

選んだ方向で、入口から主要操作、詳細・根拠へ至る一続きの体験を、実際の内容と素材で先に仕上げてください。その後に全体へ展開してください。フレームワークやエージェント構成は、この設計に必要なものを選びます。工程や機能の数を品質の根拠にしないでください。

検査では、原文との照合、主要操作、空状態・境界例、キーボード、狭い画面、文字組み・余白・画像・一貫性を確認してください。スクリーンショットは保存するだけでなく見てください。問題を具体的な画面と行動で示し、必要なら上流の構造へ戻って直してください。最良の版を保持し、評価点が上がることと品質が上がることを混同しないでください。

`WORKFLOW.md` と `EVALUATION.md` は使える判断材料です。目的に合う範囲で参照し、工程の全実施を目的にしないでください。長い作業の現状は `work/state.md` に短く残してください。完了時は、成果物、実行方法、主な設計判断、実際に行った検証、残る限界を報告してください。
